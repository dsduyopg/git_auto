## 0. 第一次使用：必做的 3 件事

### 0.1 安装 Git
下载 <https://git-scm.com/download/win> ，一路点 Next 装完。

### 0.2 生成 SSH 钥匙（每台电脑只需一次）
双击根目录 **`生成SSH密钥.bat`** → 输入名称后回车 → 公钥自动复制到剪贴板。

然后把公钥添加到你的平台账号：
- **Gitee**：登录 → 设置 → SSH公钥 → 粘贴保存
- **GitHub**：Settings → SSH and GPG keys → New SSH key → 粘贴保存

> 这把"钥匙"不配好，后面所有同步都会连接失败。

### 0.3 跑一次环境自检
双击根目录 **`环境自检.bat`**，它会检查 Git / SSH 钥匙 / nssm 是否就绪，并提示下一步。

## 场景 A：本地文件夹自动推送到云端

**效果**：文件夹里增删改任何文件 → 自动提交并推送到云端；开机自动运行。

### 前提
在 Gitee / GitHub 网页上**先建一个空仓库**（不会的话搜索"Gitee 新建仓库"）。

### 步骤
1. 双击 **`新建自动推送仓库.bat`**
2. 按提示输入：
   - **仓库本地路径**，如 `D:\我的项目`
   - **平台**：`1` = Gitee，`2` = GitHub
   - **远端 SSH 地址**，如 `git@gitee.com:你的用户名/仓库名.git`
   - **user.name / user.email**（Git 提交署名，随便填或填真实邮箱）
   - **不想推送的目录/文件**（可选，多个用逗号分隔，如 `内部资料, logs`），直接回车跳过
3. 脚本自动完成：初始化仓库 → 配置远端 → 安装同步服务 → 启动

### 验证
在文件夹里新建一个 txt 文件，等几秒，去 Gitee/GitHub 网页刷新，文件应已出现。

### 注意
- 首次推送可能需要几十秒（取决于文件夹大小）
- 同步服务名为 `GitAutoSync` 开头，可在 `服务管理.bat` `[1]` 查看

## 场景 B：云端仓库拉取到本地

**效果**：把任意远端仓库克隆到本地指定目录；再运行一次即更新。

### 步骤
1. 双击 **`新建云端镜像拉取.bat`**
2. 输入：
   - **远端地址**，如 `git@gitee.com:任何人/仓库.git`
   - **目标目录**，如 `D:\下载区\某某项目`
   - **分支**（直接回车用默认分支）
3. 立即克隆完成，内容马上出现在目标目录

### 更新
想拉最新版，再运行一次同一个 bat 即可。

## 场景 C：每小时自动拉取更新

**效果**：登记过的镜像目录，每小时自动从云端拉取一次。

### 步骤
1. 先按**场景 B** 至少建过一个拉取镜像
2. 双击 **`安装定时拉取服务.bat`**（会请求管理员权限，点"是"）
3. 之后每小时自动拉取所有已登记的镜像

### 调整间隔
`服务管理.bat` → **`[F]` 设置定时拉取间隔**。

> ⚠️ **重要**：定时拉取会执行 `git reset --hard` 并清理镜像目录中的未跟踪文件，**镜像目录里你自己放的东西会被覆盖/删除**。
> 只想保留本地改动、不清理未跟踪文件：设置系统环境变量 `GIT_MIRROR_CLEAN=0` 后重启服务。

## 场景 D：某些目录不想同步

### 情况 1：新建仓库时排除
在**场景 A 第 2 步**的"不想推送的目录/文件"里直接填写，多个用逗号分隔。

### 情况 2：已有仓库，事后排除
1. 双击 **`移除推送目录.bat`**，或 `服务管理.bat` → **`[H]`**
2. 输入 **Git 仓库路径**（也可以是仓库里的子目录，脚本会自动向上找到仓库根）
3. 输入要停止推送的**目录/文件**，如 `内部资料\私密文件`
4. 脚本会：写入 `.gitignore` → 从 Git 索引移除（**本地文件保留**）→ 更新同步脚本
5. 按提示选择是否立即提交推送；若同步服务正在运行，**重启对应服务**后规则生效

> ⚠️ 如果这些文件之前已经推送到云端，普通移除只能让**最新版本**不再包含它，**历史提交里仍然存在**。需要彻底清除请用 `git filter-repo`，或新建仓库重新上传。

## 场景 E：开启邮件通知

默认**关闭**，一封都不发。开启后可收到同步成功/失败通知。

### E1. 先配置邮箱（每台电脑只需一次）
1. 双击 **`05-邮件通知\配置SMTP.bat`**（根目录 `邮件通知配置.bat` 是同一入口）
2. 选 **[1] 开启并绑定 SMTP**
3. 选邮箱类型（内置 QQ / 163 / Gmail 预设，也可自定义）
4. 填：**发件邮箱** + **SMTP 授权码** + **收件人**
5. 选 **[3] 发一封测试邮件** → 收到即配置成功

**关于授权码**（不是邮箱登录密码）：
- QQ 邮箱：设置 → 账户 → POP3/SMTP服务 → **生成授权码**
- 163 邮箱：设置 → POP3/SMTP/IMAP → 开启 → **生成授权码**

想停用：选 **[2] 关闭邮件通知**。

### E2. 按仓库开关（推荐做法）
1. **管理员身份**运行 `服务管理.bat` → **`[I]` 邮件服务管理**
2. 菜单列出本机所有**已安装同步服务的仓库**（自动扫描，换电脑通用）
3. **输入序号** → 切换该仓库的邮件通知开关
   - `[A]` 全部启用
   - `[N]` 全部关闭
4. 按 **`[S]`** 安装并启动 `GitAutoSyncMail` 监控服务（会自动发一封测试邮件确认可用）
   - `[X]` 停止监控服务
   - `[0]` 返回上级菜单

**以后新增仓库**：只要给它装了同步服务，重新进 `[I]` 就能看到，输序号即可加入，**不用改任何脚本**。

### E3. 相关说明
- 邮件由独立的 `GitAutoSyncMail` 监控服务发送，**不修改你的任何同步脚本**
- 监控服务每 30 秒检查一次；发现新提交才发信
- **首次登记某仓库只记录状态、不发信**，避免历史提交造成群发轰炸
- 同步失败邮件带 **30 分钟节流**，不会反复刷屏
- 配置文件：`%ProgramData%\GitAutoSync\mail_config.txt`（**仅保存在你本机，不要外传**）
- 监控日志：`%ProgramData%\GitAutoSync\mail_monitor.log`

### E4. 关于旧的 `[N]` 菜单
`[N] 为指定仓库开启/升级邮件通知` 是早期实现方式（直接把邮件逻辑写入同步脚本）。
**推荐使用 `[I]`**。`[I]` 启用某仓库时会自动关闭该仓库脚本里的旧邮件逻辑，避免重复发信。

## 场景 F：日常管理与服务维护

双击 **`服务管理.bat`**（自动请求管理员权限）进入总菜单。

### 菜单全表

| 按键 | 作用 | 什么时候用 |
|---|---|---|
| `[1]` | 查看所有服务状态 | 想确认同步是否在跑 |
| `[2]` | 启动所有同步服务 | 批量启动 |
| `[3]` | 停止所有同步服务 | 批量停止 |
| `[4]` | 修复所有同步服务 | 服务异常、不同步了 |
| `[5]` | 彻底重建所有服务 | 服务"已标记删除"、开机不自启 |
| `[6]` | 卸载所有同步服务 | 不想要了 |
| `[7]` | 打开使用文档 | 查文档 |
| `[8]` | 新建自动推送仓库 | 场景 A |
| `[9]` | 新建云端镜像拉取 | 场景 B |
| `[A]` | 安装定时拉取服务 | 场景 C |
| `[B]` | 生成 SSH 密钥 | 首次配置 |
| `[C]` | 启动指定服务 | 只启某一个 |
| `[D]` | 停止指定服务 | 只停某一个 |
| `[R]` | 重启指定服务（重载脚本） | 改了脚本/配置后生效 |
| `[E]` | 卸载指定服务并删除仓库 | 移除单个仓库 |
| `[F]` | 设置定时拉取间隔 | 调整拉取频率 |
| `[H]` | 删除/排除仓库里的子目录 | 场景 D |
| `[G]` | 关于本工具 | 查看版本与作者 |
| `[M]` | 邮件通知配置（SMTP 总开关） | 场景 E1 |
| `[I]` | 邮件服务管理（按仓库开关） | 场景 E2（推荐） |
| `[N]` | 旧版方式开启邮件通知 | 不推荐 |
| `[0]` | 退出 | — |

## 场景 G：出错了怎么排查

| 现象 | 原因 | 解决办法 |
|---|---|---|
| 双击 bat 一闪而过 | bat 与 ps1 不在同一目录，或 ps1 被改名 | 保持原文件名、放同一文件夹 |
| 提示找不到 SSH 密钥 | 没生成钥匙 | 运行 `生成SSH密钥.bat` |
| `Permission denied (publickey)` | 公钥没加到平台账号 | 重新添加公钥（0.2 节） |
| 装服务提示权限不足 | 不是管理员 | 右键 → **以管理员身份运行** |
| 同步卡在 `index.lock` | 上次异常中断留下锁文件 | 脚本会自动清理；仍卡住运行 `修复服务.bat` |
| 服务显示 PAUSED / 启动失败 | 服务损坏 | `修复服务.bat`；不行用 `彻底重建服务.bat` |
| 定时拉取把我的文件删了 | 镜像目录被强制同步 | 设 `GIT_MIRROR_CLEAN=0`，镜像目录不要放私人文件 |
| 邮件收不到 | SMTP 未开启或授权码错误 | 用 `配置SMTP.bat` `[3]` 发测试邮件定位 |
| `[I]` 里看不到仓库 | 该仓库没装同步服务 | 先用 `新建自动推送仓库.bat` 装服务 |

### 查日志
- 邮件监控日志：`%ProgramData%\GitAutoSync\mail_monitor.log`
- 服务状态：`服务管理.bat` → `[1]`

## 场景 H：完全卸载

1. `服务管理.bat` → **`[6]` 卸载所有同步服务**（或 `[6]`→`[E]` 卸载指定服务）
2. 如需连仓库一起删除，用 **`[E]` 卸载指定服务并删除仓库**（会询问确认）
3. 删除工具包文件夹即可

> 卸载服务不会删除你的本地文件，除非你明确选择"删除仓库"。
> 想保留文件：先备份，再卸载。

手动卸载（进阶）：
```
net stop 服务名
nssm remove 服务名 confirm
```

## 附录：通用性与隐私说明

**本包为通用发布版，可直接分发给他人使用。**

| 检查项 | 状态 |
|---|---|
| 含个人电脑路径 | ❌ 无（全部使用相对路径与系统环境变量） |
| 含账号 / 密码 / SMTP 授权码 | ❌ 无（由使用者本机输入，不外传） |
| 含服务器 IP 或内网地址 | ❌ 无 |
| 需要联网下载依赖 | ❌ 不需要（nssm 已内置） |

### 使用者数据的存放位置
| 数据 | 位置 |
|---|---|
| SMTP 邮件配置（含授权码） | `%ProgramData%\GitAutoSync\mail_config.txt` |
| 启用邮件的仓库列表 | `%ProgramData%\GitAutoSync\mail_enabled_repos.txt` |
| 邮件监控服务日志 | `%ProgramData%\GitAutoSync\mail_monitor.log` |
| 拉取镜像登记表 | `%USERPROFILE%\git_mirror_config.txt` |

> `mail_config.txt` 里有你的**邮箱授权码**，请勿外传该文件。

### 换电脑 / 给别人用
把整个文件夹复制过去即可，脚本会自动适配新环境，无需修改任何内容。
